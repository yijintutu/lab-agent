## 一、当前阶段定位（一句话）

**第 1-5 节**：前端框架 + 后端框架 + 登录接口，两端各自成型但是"两张皮"。

**第 6-8 节**：给系统补齐了"登录鉴权体系（JWT）+ 统一响应/异常规范 + 前后端真正联调"，**至此登录功能形成完整闭环，前后端已经打通。**

你仍然处于大路线的 **阶段①（业务系统打地基）**，但地基里的"用户认证 + 通信管道"已经完工，接下来是在地基上盖业务房间（实验室、设备、预约）。

## 二、第 6-8 节逐节讲解

### 第 6 节：后端 JWT 用户认证

**解决的问题**：第 5 节登录成功只返回用户信息，没有任何"凭证"。HTTP 请求是无状态的——后端无法知道"这次请求是谁发来的"，也无法保护"必须登录才能访问"的接口。

**JWT（JSON Web Token）的工作机制**：

```
登录：校验账号密码 → 后端用密钥"签发"一个 token（字符串）→ 返回给前端
之后：前端每次请求在请求头带上 Authorization: Bearer <token>
      → 后端用同一密钥"验签"解析 → 知道是哪个用户 → 放行或拒绝
```

本节新增的文件和功能：

| 文件 | 提供的功能 |
| --- | --- |
| `utils/password.py` | `hash_password` 注册时把明文密码哈希成乱码存储；`verify_password` 登录时用 bcrypt 安全比对（数据库里不再存明文密码） |
| `utils/jwt.py` | `create_access_token(user_id)` 签发 token（内含用户 id 和过期时间 exp）；`decode_access_token(token)` 验签并解析 |
| `dependencies/auth.py` | `oauth2_scheme` 自动从请求头提取 Bearer token；`get_current_user` 依赖：解析 token → 查用户 → 校验状态，任何接口参数写上它就必须先登录 |
| `api/user.py` | GET `/api/user/info`：第一个"需要登录"的示例接口，返回当前用户信息 |
| `.env` / `config.py` | 新增 JWT 密钥、算法、过期时长配置 |

登录接口同步升级：用 `verify_password` 替代明文比对、校验账号是否被禁用、成功后返回 `{token, user}`。

> 类比：JWT 就像进大楼时前台给你的"访客手环"，上面有你的编号和当天有效期限；之后进每个房间刷手环即可，不用每次都回前台报身份证。

### 第 7 节：统一响应格式 + 全局异常处理

**解决的问题**：每个接口各自返回不同结构的字典、出错时各自写返回值，前端难以统一处理，代码重复。

| 文件 | 提供的功能 |
| --- | --- |
| `common/response.py` | 统一响应模型 `Response{code, message, data}`，并提供 `Response.success()` / `Response.error()` 工厂方法，全项目返回格式统一 |
| `common/exceptions.py` | ① `BusinessException` 自定义业务异常，业务失败直接 `raise`；② 四个异常处理器，分别接管：业务异常、HTTP 异常（401/403 等）、参数校验异常（422）、全局未知异常兜底（500） |
| `main.py` | 统一注册四个异常处理器（全局兜底必须最后注册） |
| `schemas/auth.py` | 新增 `LoginResponse`（token + user 两个字段） |

**这一节带来的编程思想变化**：从"出错就 return 一个错误字典"变成"出错就抛异常，由统一处理器接管"。业务代码只关心正常流程，错误处理被集中收口——这就是"AOP 面向切面"思想的雏形。

### 第 8 节：Vue 封装 axios 并实现前后端联调（关键里程碑）

**解决的问题**：前端登录页一直是 `setTimeout` 假登录，后端接口从未被真正调用；且前端 5173、后端 8000 端口不同，浏览器有跨域限制。

**本节做了三件事：**

**1）解决跨域（双保险）**
- 后端 `main.py` 配置 CORS 中间件，明确允许 5173 端口、允许携带凭证；
- 前端 `vite.config.js` 配置开发代理：所有 `/api` 开头的请求由 Vite 开发服务器转发给 8000，浏览器看到的始终是同源请求，不会触发跨域拦截。

**2）封装前端通信层（3 个文件，以后天天用）**

| 文件 | 提供的功能 |
| --- | --- |
| `utils/auth.js` | token 和用户信息的 localStorage 增删改查 + `logout()` 统一清理 |
| `utils/user.js` | `useUser()` 组合式函数：提供全局响应式 `userInfo` 和保存登录数据、登出、更新、重载方法 |
| `utils/request.js` | axios 实例：**请求拦截器**自动给每个请求加 Bearer token；**响应拦截器**统一识别业务码、401 自动登出跳登录、网络异常弹提示 |
| `api/auth.js` | `loginApi()`：把登录接口地址和参数封装成一个函数，页面直接调用 |

**3）页面接入真实接口**
- `Login.vue`：`setTimeout` 换成 `await loginApi(form)`，成功 → `saveLoginData` 存凭证 → 跳首页；失败由拦截器统一提示；
- `Home.vue`：显示真实的当前登录用户名和角色；
- `Layout.vue`：右上角显示真实用户名，下拉菜单支持退出登录（带二次确认）；
- `router/index.js`：**路由守卫** `beforeEach`——没有 token 时访问任何后台页面都被拦截到登录页。

> 至此，前端形成了固定的"请求四件套"：**页面 → api/xxx.js（接口函数）→ utils/request.js（拦截器）→ 后端**。以后所有业务页面都走这条管道。

## 四、打通后的完整请求链路（必须看懂）

**登录链路：**

```
Login.vue 点登录
  → api/auth.js loginApi(form)
  → request.js：请求拦截器（此时还没有 token）
  → POST /api/auth/login（经 Vite 代理 5173 → 8000）
  → 后端 api/auth.py：查用户 → verify_password → 校验状态
  → create_access_token 签发 token
  → Response.success 返回 {code:200, data:{token, user}}
  → 前端响应拦截器确认 code=200
  → saveLoginData：token/user 存入 localStorage
  → 跳转 /manager/home，路由守卫放行
```

**登录后访问受保护接口（如 /api/user/info）：**

```
页面发请求
  → 请求拦截器自动加 Authorization: Bearer <token>
  → 后端 get_current_user：oauth2_scheme 取 token → decode 验签 → 查用户 → 校验状态
  → 合法：接口执行并返回
  → 过期/伪造/被禁用：401 → 前端响应拦截器自动 logout 并跳登录页
```

## 五、现存问题清单（按优先级）

1. **登录需要一条真实用户数据**：密码现在是 bcrypt 哈希，手动往 users 表插明文密码无法登录。需要：写一个初始化脚本（调用 `hash_password` 生成 admin），或用教程给的在线 bcrypt 工具生成哈希后插入。
2. **`api/auth.py` 顶部有两行垃圾导入**：`import token` 和 `from h11 import Response`（VSCode 自动误导入），虽不影响运行（后面的正确导入会覆盖），但应删除。
3. **后端缺注册接口**：Register.vue 仍是模拟逻辑；补注册接口时要用 `hash_password` 存哈希密码。
4. **`api/user.py` 风格不统一**：还在手写字典返回，可改用 `Response.success()`。
5. **业务模块全部未开始**：实验室、设备、预约三张核心表和对应接口、页面都是空白。
6. 学生端页面（实验室列表/详情/我的预约）尚未规划路由。
