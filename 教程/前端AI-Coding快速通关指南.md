# 前端 AI Coding 快速通关指南（写给不懂 JS 的你）

> 目标：不成为前端工程师，而是达到 **"看得懂结构、问得对需求、验得了结果"**，把写页面的活交给 AI，你的精力留给后端和 AI Agent 主线。

---

## 一、先定目标：你要达到什么水平

| 能力 | 具体标准 |
| --- | --- |
| 看得懂 | 打开任意 `.vue` 文件，能说出 template / script / style 三块各在干嘛；能看懂页面跳转和请求走向 |
| 问得对 | 能给 AI 提供"接口长什么样 + 参考哪个现有页面 + 要什么功能"，让它一次写对 |
| 验得了 | 会启动项目、会在浏览器点一遍功能、会看报错、会看 AI 改了哪些文件 |

**明确放弃（不花时间）**：手写复杂 JS 逻辑、背 API、CSS 精调、自己从零造组件。

---

## 二、用什么工具（三选一）

| 方案 | 工具 | 适合场景 |
| --- | --- | --- |
| A（最推荐） | **Trae**（国内免费）或 **Cursor**：AI 原生 IDE，能直接读整个项目、改文件、跑命令 | 主力写页面，体验最丝滑 |
| B | **VSCode + Cline 插件**（或 Continue / GitHub Copilot） | 不想换编辑器 |
| C（最朴素） | 继续用**豆包对话**：把文件内容和报错贴给我，我给完整代码你粘贴 | 完全可控，适合第一个页面 |

**建议组合**：用 Trae/Cursor 生成和修改页面（干体力活），用豆包做"逐段讲解 + code review + 排查疑难"（当老师）。

> 无论用哪个，先让 AI 读这三样东西：① 整个 `frontend/src` 目录；② 后端接口文档 `http://127.0.0.1:8000/docs`（后端启动后可打开）；③ 本项目 `.prettierrc.json` 代码风格。

---

## 三、核心工作流：每个页面都走"五步闭环"

```
① 备料  →  ② 生成  →  ③ 看改动  →  ④ 跑验  →  ⑤ 追问/修复
```

1. **备料**：告诉 AI 三件事——后端接口（地址、方法、字段）、参考项目里哪个文件、要哪些功能。
2. **生成**：要求 AI **先列出"要新增/修改哪些文件"，你确认后再写代码**，防止它乱改。
3. **看改动（diff）**：逐文件看它改了什么。看不懂的地方直接问"这段为什么这么写"。
4. **跑验**：`npm run dev` 启动，浏览器把功能点一遍（列表、搜索、分页、新增、编辑、删除、校验）。
5. **追问**：让 AI 逐段讲解；有问题贴上报错让它修。

**安全绳**：
- 项目先初始化 git，**每次让 AI 大改前先 commit 一次**，改坏了能一键回滚；
- 一次只让 AI 做一个页面，不要一次让它做一整套。

## 四、必须掌握的 10 个最小前端知识点

> 标准不是"会写"，而是"在 AI 生成的代码里能认出来、知道它干嘛"。

| # | 知识点 | 看懂的标准（一句话） |
| --- | --- | --- |
| 1 | `.vue` 单文件结构 | template=页面长什么样；script=数据和逻辑；style=样式 |
| 2 | `{{ 变量 }}` 插值 | 把数据显示到页面上 |
| 3 | `v-model` | 表单输入框和数据双向绑定（输入即同步） |
| 4 | `v-for` | 循环数组，把列表一行行渲染出来 |
| 5 | `@click` 等事件 | 用户点按钮/输内容时触发哪个函数 |
| 6 | `:属性` 绑定 | 组件的属性值由数据决定（如 `:loading="loading"`） |
| 7 | `ref` / `reactive` | 响应式数据：数据一变，页面自动更新 |
| 8 | 路由 | URL 和页面对应表；`router.push` 编程跳转；`<router-link>` 链接跳转 |
| 9 | 请求链路 | 页面 → `api/xxx.js` → `utils/request.js`（自动带 token）→ 后端 |
| 10 | 组合式函数 | `useUser()` 这种把可复用逻辑打包的函数 |

**学法建议**：不要看泛泛的教程，**让 AI 用你项目里的真实代码逐个讲这 10 个点**（用下面的"讲解模板"），讲一个对应一个文件，立刻就能懂。

## 六、页面验收清单（AI 写完，你照着勾）

**功能层面：**
- [ ] 进页面列表自动加载
- [ ] 关键词搜索、重置生效
- [ ] 翻页、改每页条数生效
- [ ] 新增：弹窗打开 → 必填校验 → 提交后列表刷新
- [ ] 编辑：弹窗能**回显**原数据 → 保存后列表更新
- [ ] 删除：有二次确认 → 确认后列表刷新
- [ ] 各种操作有 loading；失败有提示
- [ ] 手动把后端关掉，页面应提示"网络异常"而不是白屏报错

**代码层面（让 AI 自查，你抽查）：**
- [ ] 用的是项目统一的 `request`，没有硬编码地址
- [ ] 没有无用 import（你项目 `api/auth.py` 里 `import token`、`from h11 import Response` 就是反面教材）
- [ ] 没有擅自安装新依赖
- [ ] 字段名和后端一致

## 七、AI 写前端最容易犯的 5 个错（重点盯防）

1. **硬编码地址**：绕过你的 request 封装，直接写 `axios.get('http://localhost:8000/...')` → 模板里明确禁止。
2. **臆造接口/字段**：编一个后端不存在的 URL 或字段名 → 一切以 `/docs` 为准，让它先读后端。
3. **乱装依赖**：为一个小功能装个新库 → 模板里写明"不引入新依赖"。
4. **风格漂移**：加分号、双引号、写法和现有页面不统一 → 让它读 `.prettierrc.json`。
5. **一次改太多文件**：diff 看不过来、出错难定位 → 一次一个页面、一个闭环。

| 页面 | 你的角色 | 目标 |

## 九、配合后端的最佳顺序（少走弯路）

```
先写后端接口（后端你熟，或同样让 AI 按现有套路写）
  → 启动后端，打开 /docs 确认接口和字段
  → 再让前端 AI 对着 /docs 生成页面
  → 浏览器联调验收
```

不要在后端接口还没定的时候让前端 AI 盲写——那会逼它臆造接口，返工最多。
