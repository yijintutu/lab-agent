# 智能实验室预约系统（课程总纲）

## 一、系统简介

- 定位：从真实业务系统出发，逐步接入 AI 能力
- 关键认知：不是简单调用一次大模型 API
- 最终技术栈
  - 前端：Vue3 + Vite + Element Plus
  - 后端：Python + FastAPI + SQLAlchemy
  - 数据库：MySQL
  - AI：LangChain、ChromaDB、RAG、LangGraph

## 二、为什么选择这个项目

- 痛点：学了很多技术，却不会组合到真实项目中
- 孤立的技能点
  - 学 FastAPI → 只会写 CRUD
  - 学 LangChain → 只会调用大模型
  - 学 RAG → 只会做知识库问答
  - 学 LangGraph → 只会画工作流
- 课程目标：用一个完整项目把这些技术串联起来

## 三、项目背景

- 学校拥有多个实验室
  - 人工智能实验室
  - 机器人实验室
  - 云计算实验室
  - 软件工程实验室
- 各实验室的差异
  - 实验设备不同
  - 容纳人数不同
  - 开放时间不同
  - 使用规则不同
- 传统预约流程
  - 查看实验室
  - 了解实验室设备
  - 选择预约时间
  - 提交预约申请
  - 管理员审核
- AI 目标：一句话完成查询与预约
  - “明天下午要一个能容纳 20 人的实验室”
  - “哪个实验室有 RTX4090”
  - “帮我预约明天下午两点到五点的 AI 实验室”

## 四、项目开发路线（核心主线）

- 总路线：业务系统 → AI 能力 → AI Agent
- 第一阶段：实验室预约业务系统
  - 学生端功能
    - 用户登录
    - 实验室列表
    - 实验室详情
    - 实验室预约
    - 我的预约
    - 取消预约
  - 管理端功能
    - 实验室管理
    - 设备管理
    - 预约审核
    - 用户管理
  - 使用技术：Vue3、FastAPI、SQLAlchemy、MySQL
- 第二阶段：接入大模型
  - 产物：AI 实验室助手（聊天式咨询）
  - 典型问题：开放到几点、有哪些设备、如何预约
  - 学习点：大模型 API、Prompt、Message、AI 对话
- 第三阶段：RAG 实验室知识库
  - 解决问题：大模型不知道学校的私有规则
  - 导入资料
    - 实验室预约规则
    - 实验室安全规范
    - 设备使用规范
    - 实验室管理制度
  - 工作流程
    - 用户问题
    - 检索相关知识（ChromaDB）
    - 获取相关文档
    - 大模型生成回答
- 第四阶段：Tool Calling（工具调用）
  - 解决问题：AI 无法操作实时业务数据
  - 工作流程
    - 用户问题
    - AI 判断是否调用工具
    - Tool Calling
    - 查询数据库
    - 返回真实数据
    - AI 生成回答
  - 示例工具：search_laboratory()
  - 学习点：LangChain、Tool、Tool Calling、Structured Output
- 第五阶段：LangGraph 智能预约
  - 特征：多步骤、有状态的业务流程
  - 工作流程
    - 用户请求
    - 提取预约信息
    - 判断信息是否完整
    - 不完整 → 继续追问
    - 完整 → 查询实验室
    - 查询空闲时间
    - 推荐实验室方案
    - 等待用户确认（Human-in-the-loop）
    - 创建预约
  - 学习点：State、Node、Edge、Conditional Edge、ToolNode、Human-in-the-loop

## 五、完整技术架构

- 前端 Vue3
  - 传统业务 API
  - AI Chat
- 后端 FastAPI
  - Service（业务服务）
  - Tool（AI 工具）
  - RAG（知识检索）
  - Memory（记忆）
- 数据层
  - MySQL（业务数据）
  - ChromaDB（向量知识库）

## 六、核心思想

- AI 不是重新开发一套业务系统
- AI 是为原有业务系统增加一个智能入口
- 传统链路：点击按钮 → API → 业务系统 → 数据库
- AI 链路：自然语言 → AI Agent → 调用业务工具 → 业务系统 → 数据库

## 七、课程开发顺序（7 个部分）

- 第一部分：Python + FastAPI 基础
- 第二部分：实验室预约业务系统
- 第三部分：接入大模型
- 第四部分：RAG 实验室知识库
- 第五部分：Tool Calling
- 第六部分：LangGraph
- 第七部分：AI 智能预约 Agent

## 八、已落地的前 5 节实操

- 第 1 节：搭建环境、创建前端 Vue 工程
  - 安装软件：VSCode、NodeJS
  - 验证环境：node -v、npm -v
  - 配置 npm 国内镜像
  - VSCode 插件：Vue-Official、Prettier
  - 创建工程：npm create vue@latest
  - Prettier 配置：.prettierrc.json
  - 保存自动格式化：settings.json
  - 安装 Element Plus 与图标库
  - 配置中文国际化 zh-cn
  - 编写全局样式 global.css
  - main.js 中完成总组装
- 第 2 节：搭建前端 Vue 主体框架
  - App.vue 只保留 router-view 作为出口
  - Layout 布局
    - el-header 顶部标题栏
    - el-aside 左侧菜单
    - el-main 主内容区（嵌套 router-view）
  - 路由配置：/manager 父路由 + 子路由
  - Home.vue 系统首页
- 第 3 节：开发前端登录页面
  - Login.vue
    - el-form 账号密码表单
    - 输入框图标、按钮 loading
    - 登录成功后跳转（当前为模拟）
  - Register.vue 注册页
  - 路由补充 /login、/register
- 第 4 节：搭建后端 FastAPI 工程
  - 安装软件：Python、MySQL、Navicat
  - 配置 pip 阿里云镜像 pip.ini
  - 创建并激活虚拟环境 .venv
  - 编写 requirements.txt 并安装依赖
  - 编写第一个接口 Hello FastAPI
  - uvicorn 启动并测试
- 第 5 节：开发后端登录 API
  - .env：配置 DATABASE_URL
  - config.py：Settings 自动读取 .env
  - database.py
    - engine 数据库引擎
    - SessionLocal 会话工厂
    - get_db 依赖注入（请求结束自动关闭）
    - Base 公共基类（id、create_time、update_time）
  - models/user.py：User 模型映射 users 表
  - create_all：按模型自动建表
  - schemas
    - LoginRequest：校验入参
    - UserResponse：规范出参（from_attributes）
  - api/auth.py：POST /api/auth/login
  - main.py：注册路由、启动即建表
  - ApiPost 工具测试接口
