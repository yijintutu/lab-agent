# 智能实验室预约系统 · 项目路线讲解

> 面向零基础同学：这份文档帮你回答三个问题——
> ① 这门课整体在干什么？② 前 5 节每一步操作是为了什么？③ 你的项目现在走到哪、下一步该做什么？

---

## 一、先建立全局认知：这门课在做什么

**一句话概括**：先做一个传统的"实验室预约网站"（能登录、能看实验室、能提交预约），再一步步给它装上"AI 大脑"，最终让用户用一句自然语言就能完成预约。

课程不是一上来就写 AI，而是走一条非常清晰的路线：

```
业务系统  →  AI 能力  →  AI Agent
（打地基）   （装嘴巴）   （装大脑）
```

- **业务系统**：预约网站本身。实验室、设备、用户、预约单这些数据和功能必须先存在。
- **AI 能力**：让用户能"聊天"，先能回答知识问题，再能查询真实数据。
- **AI Agent**：AI 不只是回答问题，而是像一个前台办事员，自己判断、自己调用系统功能，多步骤地帮你把预约办完。

**为什么必须先做业务系统？** 因为 AI 不是凭空办事的，它最终要调用系统里现成的功能（查实验室、查空闲时间、创建预约）。如果业务系统不存在，AI 就成了"无米之炊"。记住课程最核心的一句话：

> **AI 不是重新开发一套系统，而是给传统业务系统增加一个更智能的入口。**

## 二、五个阶段的知识脉络

| 阶段 | 要解决的问题 | 关键技术 | 最终产物 |
| --- | --- | --- | --- |
| ① 业务系统 | 让预约这件事能在线完成 | Vue3、FastAPI、SQLAlchemy、MySQL | 学生端 + 管理端网站 |
| ② 接入大模型 | 用户想用"聊天"咨询问题 | 大模型 API、Prompt、Message | AI 实验室助手（对话） |
| ③ RAG 知识库 | 大模型不知道学校的私有规则 | RAG、ChromaDB、Embedding | 能答校规的知识库问答 |
| ④ Tool Calling | AI 拿不到实时变化的业务数据 | LangChain、Tool、Structured Output | AI 能查询真实数据库 |
| ⑤ LangGraph 智能预约 | 预约是多步骤、需要确认的流程 | LangGraph、State、Node、条件边、Human-in-the-loop | AI 智能预约 Agent |

**阶段之间是"发现问题 → 解决问题"的递进关系**，不是随便排列的：

1. 只会聊天 → 答不了学校私有规则 → 所以需要 **RAG**（阶段③）。
2. 能答规则了 → 但"现在哪些实验室能约"是实时数据，知识库里没有 → 所以需要 **Tool Calling**（阶段④）。
3. 能查数据了 → 但完整预约要"提取信息→检查→推荐→等用户确认→下单"一整套流程 → 所以需要 **LangGraph**（阶段⑤）。

## 三、前 5 节实操逐节讲解（每一步在干什么）

### 第 1 节：搭建环境 + 创建前端 Vue 工程

这一节的目标是：**在电脑上准备好前端开发工具，并生成一个能跑起来的 Vue 项目骨架。**

| 改造 `main.js` | 项目总入口，把上面所有东西组装起来 | 应用启动的第一站 |

> 类比：这一节就像"装修前先把水电、工具箱、建材市场（组件库）准备好，并用模板房搭出毛坯房"。

### 第 2 节：搭建前端主体框架

目标：**给管理后台搭出"顶部标题栏 + 左侧菜单 + 右侧内容区"的经典后台布局，并配好页面跳转规则。**

- **`App.vue`**：整个应用的根组件，里面只放一个 `<router-view />`，意思是"路由匹配到哪个页面，就把哪个页面显示在这里"。
- **`Layout.vue`（布局组件）**：
  - `el-header`：顶部栏，放系统 Logo、名称、当前用户。
  - `el-aside`：左侧菜单栏（系统首页 / 实验室管理 / 设备管理 / 用户管理）。
  - `el-main`：主内容区，里面再放一个 `<router-view />`，子页面在这里显示。
- **`router/index.js`（路由）**：URL 和页面的对应表。访问 `/manager/home` 就显示 Home 页面，访问 `/manager/lab` 就显示 Lab 页面。
  - 路由还支持**嵌套**：`/manager` 对应 Layout，它的"子路由"页面显示在 Layout 主区域里。
- **`Home.vue`**：第一个真正的子页面（系统首页）。

> 类比：布局组件是"房子的户型"（客厅、走廊定好了），路由是"房间门牌号对照表"，每个页面就是一个房间。

### 第 3 节：开发前端登录页面

目标：**做出登录页和注册页的界面与交互。**

- **`Login.vue`**：
  - 用 `el-form` + `el-input` 做账号、密码输入框；
  - `reactive` 定义表单数据 `form`，输入框内容会自动同步进去（Vue 的"响应式"——数据变，页面自动变）；
  - 点登录后 `loading` 转圈，模拟请求，然后跳转到后台首页。
  - **注意：这一节的登录是"假"的**——用 `setTimeout` 模拟了 0.8~2 秒网络请求，并没有验证账号密码，随便输都能进。
- **`Register.vue`**：注册表单，多了"确认密码"，并做了两次密码是否一致的前端校验。
- 路由里补充 `/login`、`register` 两个独立页面（它们不套 Layout，全屏显示）。

> 为什么先做假登录？前端开发常见做法：先把页面和交互做出来，后端接口好了再对接，前后端可以并行开发。

### 第 4 节：搭建后端 FastAPI 工程

目标：**在电脑上准备好后端运行环境，生成一个能接收 HTTP 请求的 Python Web 服务。**

| 操作 | 在干什么 | 为什么需要 |
| --- | --- | --- |
| 安装 Python | 后端语言运行环境 | 后端代码用 Python 写 |
| 安装 MySQL | 关系型数据库 | 永久保存用户、实验室、预约数据 |
| 安装 Navicat | 数据库可视化工具 | 图形界面看表、改数据，不用敲命令 |
| 配置 pip 阿里云镜像 | Python 包下载源换成国内 | 下载依赖更快 |
| `py -m venv .venv` | 创建虚拟环境 | 给本项目单独的依赖空间，不和其他项目冲突 |
| 激活 `.venv` | 进入这个独立环境 | 之后装的包只属于本项目 |
| `requirements.txt` + `pip install -r` | 声明并安装依赖 | fastapi（web 框架）、uvicorn（服务器）、sqlalchemy（操作数据库）、pymysql（连 MySQL）等 |
| 写第一个接口 `@app.get("/")` | 定义"访问根路径时返回什么" | 验证服务能跑通 |
| `uvicorn app.main:app --reload` | 启动服务，`--reload` 表示改代码自动重启 | 浏览器访问 127.0.0.1:8000 即可测试 |

> 前后端分工类比：前端是"餐厅门面和菜单"，负责给用户看；后端是"后厨"，负责处理业务逻辑；数据库是"仓库/账本"，负责存数据。

### 第 5 节：开发后端登录 API（重点，涉及后端分层思想）

目标：**写出真正校验账号密码的登录接口，并打通"后端 ↔ 数据库"。** 这一节第一次出现完整的后端分层，要重点理解。

后端代码分成了清晰的几层，各管一件事：

```
请求进来
  │
  ▼
main.py            应用入口：创建 app、注册所有路由、启动时自动建表
  │
  ▼
api/auth.py        路由层：定义 /api/auth/login，编排"查询→判断→返回"
  │
  ├── schemas/     数据契约层：LoginRequest 规定前端要传什么；
  │                UserResponse 规定返回给前端什么（自动过滤掉密码等字段）
  │
  ├── models/      数据模型层：User 类对应数据库 users 表的结构
  │
  ▼
database.py        数据库层：engine 连接、SessionLocal 会话工厂、
                   get_db 依赖（每个请求开一个会话，用完自动关）、
                   Base 公共基类（所有表都有的 id/创建时间/更新时间）
```

逐块讲解：

1. **`.env` 配置文件**：写数据库连接地址 `DATABASE_URL=mysql+pymysql://账号:密码@主机:端口/库名`。敏感信息、环境相关信息单独放这里，不写死在代码里。
2. **`config.py`**：用 `pydantic-settings` 自动读取 `.env`，全项目通过 `settings.DATABASE_URL` 使用配置。
3. **`database.py`**：
   - `engine`：数据库引擎，管理连接池，程序靠它和 MySQL 通信。
   - `SessionLocal`：会话工厂，每次请求创建一个"会话"（可以理解为一次数据库操作的上下文）。
   - `get_db()`：FastAPI 的"依赖注入"函数——接口函数参数里写 `db = Depends(get_db)`，FastAPI 就会在请求开始时自动开会话、请求结束后自动关闭，避免连接泄漏。
   - `Base`：所有模型的公共父类，统一定义 `id`（主键）、`create_time`、`update_time`，这样每张表自动带这三个字段，不用重复写。
4. **`models/user.py`（模型 Model）**：用 Python 类描述 `users` 表有哪些列（账号、密码、姓名、角色、邮箱、手机、状态……）。
5. **`Base.metadata.create_all()`**：启动时按模型定义自动建表（已存在的表不会重复建，也不会自动修改结构）。
6. **`schemas/`（模式 Schema）**：
   - `LoginRequest`：规定登录必须传 `username`、`password`，类型不对 FastAPI 自动报错。
   - `UserResponse`：规定返回哪些用户字段，**密码不在里面，天然防止把密码返回给前端**；`from_attributes=True` 表示允许直接从 ORM 对象读取数据。
7. **`api/auth.py`（路由）**：登录逻辑——
   - 按用户名查 users 表；
   - 查不到或密码不一致 → 返回业务错误码 400；
   - 匹配成功 → 用 `UserResponse.model_validate(user)` 组装安全的用户数据返回。
8. **`main.py` 注册路由**：`app.include_router(auth_router)`，接口才真正生效。
9. **ApiPost 测试**：用接口测试工具发 POST 请求验证，不必依赖前端。

> **为什么 Model 和 Schema 要分两套？**（初学者最常问）
> - **Model 管"数据库里长什么样"**，和表一一对应，包含密码等敏感字段；
> - **Schema 管"接口上传什么、回什么"**，是对外的数据格式，可以只暴露安全的字段。
> - 两者分离，数据库结构改动不会直接冲击接口，也更安全。

**一次登录请求的完整旅程（后端视角）**：

```
前端 POST /api/auth/login，带上 {"username":"admin","password":"xxx"}
  → FastAPI 用 LoginRequest 校验格式
  → get_db 打开数据库会话
  → 按 username 查 users 表
  → 比对密码
  → 成功：UserResponse 过滤字段 → 返回 {code:200, data:{...}}
  → get_db 关闭会话
```

### 一句话定位

> **你已经完成了"第 1 阶段（业务系统）的环境搭建 + 前后端登录两端的各自开发"，但前端和后端目前还是"两张皮"，没有真正连起来。**

### 当前存在的断点 / 缺口（重要）

1. **前端登录没有调用后端**：`Login.vue` 里还是 `setTimeout` 假登录，后端辛苦写的 `/api/auth/login` 还没被使用。
2. **后端没有配置 CORS**：前端跑在 5173 端口、后端在 8000 端口，浏览器出于安全会拦截跨端口请求（跨域），不配置直接调会报错。
3. **前端还没有发 HTTP 请求的工具**：没有安装 axios（或用 fetch），也没有统一的请求封装。
4. **数据库里可能还没有用户数据**：users 表建好了，但如果没手动插入一条 admin 记录，登录会一直提示账号密码错误。
5. **还没有登录凭证机制**：教程大纲里提到 JWT，目前登录成功只返回用户信息，没有 token，刷新页面登录态就丢失。
6. **业务模型/接口/页面全部未开始**：实验室、设备、预约（核心业务）还没有 Model、API 和页面。
7. **注册接口缺失**：前端有注册页，后端还没有对应的注册 API。

## 六、记住这张"能力递进"图

```
传统系统：用户点按钮 ──→ API ──→ Service ──→ 数据库
                                      ▲
AI 系统：用户说自然语言 ──→ AI Agent ──→ 调用 Tool（复用同一个 Service）──→ 数据库

阶段① 把下面这条"传统链路"修好
阶段②③④ 让 AI 能聊天、能查知识、能调工具
阶段⑤   让 AI 能多步骤地把一件事办完（并在关键处等你确认）
```

你现在的位置：**阶段① 的前半段——房子的毛坯（前端框架）和厨房（后端框架 + 登录接口）都建好了，下一步是接通水电（前后端联调），然后逐个装修房间（实验室/设备/预约业务）。**
